# 三次试飞结论（对照 auto_land_by_pose 源码）
# 日期：2026-08-06

## 1. ±0.5 m/s 水平速度脉冲 —— 不是我们的降落节点

`auto_land_by_pose` 在对准阶段只发：

- `cmd = XyzPosYawBody (14)`
- `desired_pos = [x_rel/2, y_rel/2, -drop_height]`（机体相对位置，米）
- **从不发** 水平 `desired_vel = ±0.5`

最终下压只发：

- `cmd = XyzVelYawBody (15)`
- `desired_vel = [0, 0, -land_vel]`，默认 `land_vel=0.3`（仅垂直）

因此 ULG 里 `vx/vy=±0.5` 与老师手动/其它节点指令一致，**不能用来证明视觉降落在纠偏**。

指纹对照（下次认我们的指令）：

| 来源 | 典型特征 |
|------|----------|
| 老师速度点动 | 水平 vel ±0.5，短脉冲 |
| 我们对准 | PositionTarget 由 body 相对位移换算；水平 vel 通常为 0 |
| 我们最终下压 | 仅 vz≈-0.3，vx=vy=0，持续约 last_land_time |

## 2. 「外部解锁/起飞」≠ auto_takeoff 没关掉

老师 catkin 起飞本来就会：

- Armed by external command
- Takeoff detected
- OFFBOARD

这与 `auto_takeoff:=false` **不矛盾**。要确认降落节点有没有自己起飞，看终端是否出现：

`[TX auto_takeoff/Takeoff]`

没有这行 = 降落节点没发起飞。

## 3. 已确认的代码问题：带水平偏差仍可最终下降

旧条件：

```
(xy 够准 AND z 够低)  OR  abs(z_rel) < 0.20
```

后半截会导致：**高度相对板 <20cm 时，哪怕 xy 还偏 10～20cm 也进入最终下压**——与日志 237/239 下降期仍有约 0.1m 水平偏差吻合。

已改为：**必须 xy_ok 后**，才允许 `(z_ok || very_low)` 进入最终阶段。

## 4. 指令是否进飞控 —— 下次这样验

同时开：

```bash
# 终端：降落（看 [TX ...]）
roslaunch sunray_tutorial auto_land_by_pose.launch auto_takeoff:=false

# 终端：旁路听
python3 ~/uav_worklog/scripts/watch_uav_control_cmd.py
```

判定：

1. 有 `[TX align/XyzPosYawBody]` 且 `subs>=1` → 我们发了，控制栈在听  
2. 有 `[TX ...]` 但 `subs=0` → 发了没人听（控制节点/话题名问题）  
3. 一直 `wait for pose` / `wait for tag` → 根本没进入对准，飞机动作全是老师的  
4. 监听脚本无 `[LISTEN]` → 总线上没有我们的 cmd

建议同步录 bag（勿只靠 ULG）：

```bash
rosbag record -O ~/uav_worklog/records/land_$(date +%Y%m%d_%H%M%S).bag \
  /uav1/uav_control_cmd \
  /uav1/swarm/uav_state \
  /uav1/sunray_detect/qrcode_detection_ros \
  /uav1/mavros/setpoint_raw/local \
  /uav1/mavros/local_position/pose
```
